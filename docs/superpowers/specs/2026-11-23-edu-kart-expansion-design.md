# 공부 카트 레이스 확장 설계 (6차)

## 의도
- 기존 의도 유지: 아이는 달리면서 산수·영어를 연습하고, 어른도 레이싱 자체가 재미있어야 한다.
- 이번 목표: 내용(트랙·아이템·상대·문제)을 크게 늘리고, 그 전에 1,791줄짜리 `js/game.js` 를 나눠서 앞으로 고치기 쉽게 한다.

## 목표
1. `js/game.js` 를 역할별 파일로 분리 (동작 변화 없음).
2. 문제 유형 다양화 (산수·영어 안에서).
3. 아이템 12종 (사용자 요구: 최소 10종).
4. 컴퓨터 상대 4명 → 7명, 성격 차이.
5. 지형 개선: 커브 기울기, 노면 종류, 지름길.
6. 트랙 2개 추가 (총 4개).

## 하지 않을 것
- 새 과목(국어 등) 추가. 산수·영어만 깊게 만든다. (내 결정: 사용자가 과목은 따로 말하지 않음)
- 온라인 대전, 로그인, 결제, 광고 (기존 설계 유지).
- 기존 게임의 이름·캐릭터·트랙·아이템 모양을 그대로 따라 하기. 아이템 효과는 장르에서 흔한 것이어도 이름·모양은 새로 만든다.

## 실패로 보는 것
- 분리 후 `index.html` 더블클릭으로 실행이 안 됨.
- 아이템이 너무 세서 순위가 운으로만 갈림, 또는 정답 문 통과보다 아이템이 더 중요해짐.
- 화면 효과가 문제 카드를 가려 문제를 못 읽음.
- 기존 두 트랙의 주행감이 바뀜.

## 제약
- 설치 없이 `index.html` 더블클릭(`file://`)으로 실행. 인터넷 없이도 동작 (vendor 로컬 로드 유지).
- Three.js 0.149 번들(`vendor/three-bundle.js`) 그대로. 새 의존성 없음.
- 그래픽 '빠르게' 모드에서 소프트웨어 렌더링 16fps 이상 유지.
- 점검 수단: `node test/questions.test.js`, `index.html#sim=400` 자율주행 결과.

## 방식 결정

### 파일 분리 방식
- **A. 일반 `<script>` 여러 개 + 공용 namespace `window.EK` (선택)**: 더블클릭 실행 유지. 기존 `questions.js`, `trackgen.js`, `models.js` 와 같은 방식.
- B. ES modules: 의존성이 명확하지만 `file://` 에서 막혀 로컬 서버가 필요. 실행 방식이 바뀌므로 제외.
- C. Vite 등 빌드 도구: 빌드 결과물은 더블클릭 가능하지만, 작은 프로젝트에 도구 설치와 빌드 단계가 생김. 제외.

### 작업 순서
분리 → 문제 → 아이템 + 컴퓨터 → 지형 → 트랙. 분리를 먼저 끝내야 나머지 작업이 같은 파일에서 부딪히지 않는다.

## 1. 파일 분리
- 나누는 단위 (예상): `core.js`(유틸·설정·저장·입력), `audio.js`(Sound), `render.js`(렌더러·후처리·라벨·파티클), `tracks.js`(트랙 정의 데이터), `world.js`(트랙·지형·장식·볼거리 만들기), `race.js`(경주 시작·물리·문제 문), `items.js`, `ai.js`, `hud.js`(HUD·미니맵·결과), `menu.js`(메뉴·일시정지·설정), `main.js`(루프·sim).
- 공유 상태(`game`, `settings`)는 `EK` 객체에 두고 각 파일이 참조한다.
- 확인: 분리 전후 같은 시드로 `#sim` 결과가 같아야 한다. 지금은 `Math.random` 을 써서 결과가 매번 다르므로, 분리 전에 sim 모드에서만 시드 고정 난수를 쓰게 바꾼다.

## 2. 문제 유형
### 산수
| 수준 | 기존 | 추가 |
|------|------|------|
| 1~2학년 | 덧셈·뺄셈 | 빈칸 채우기(□ + 3 = 7), 크기 비교(8 ○ 5 → >, <, =), 몇 개인지 세기(🍎×7) |
| 3~4학년 | 구구단, 두 자리 덧뺄셈 | 빈칸 곱셈(4 × □ = 28), 시계 읽기(🕒 3:30 형식 텍스트), 길이 단위(1m = □cm) |
| 5~6학년 | 곱셈·나눗셈·세 자리 | 분수 크기 비교, 분수 덧셈(분모 같음), 소수 덧셈, 혼합 계산(2 + 3 × 4) |

### 영어
| 수준 | 기존 | 추가 |
|------|------|------|
| 1 | 그림 → 단어 | 듣고 고르기(음성만, 보기는 그림), 첫 글자 고르기(🐱 → c / d / b) |
| 2 | 단어 → 뜻 | 빠진 글자(c_t → a / o / u) |
| 3 | 뜻 → 단어 | 철자 맞는 것 고르기(elephant / elefant / elephent), 반대말(big ↔ small) |

- 단어 약 50개 → 약 120개 (동물·음식·학교·날씨·색깔·숫자·몸).
- 한 경주 안에서는 유형을 섞어 낸다. 틀린 문제 다시 내기(30%)는 그대로.
- 보기는 문 3개라 항상 3개. 보기 글자 길이는 지금 문 판에 들어가는 길이 이하.
- `test/questions.test.js` 에 새 유형마다 "정답이 보기에 정확히 하나 있다", "보기 중복 없음" 검사를 추가.

## 3. 아이템 12종
아이템 상자에서 무작위로 나온다. 뒤에 있을수록 센 아이템이 잘 나온다(순위별 확률표). 컴퓨터도 모든 아이템을 쓴다.

| # | 이름 | 모양 | 효과 | 주로 나오는 순위 |
|---|------|------|------|------|
| 1 | 부스터 (기존) | 🚀 | 2초 가속 | 전체 |
| 2 | 바나나 (기존) | 🍌 | 뒤에 놓음, 밟으면 미끄러져 돎 | 앞 |
| 3 | 부스터 3개 | 🚀🚀🚀 | 부스터를 세 번 나눠 씀 | 중간~뒤 |
| 4 | 방패 | 🛡️ | 8초 동안 공격·바나나·충돌 1회를 막음 | 앞~중간 |
| 5 | 물풍선 | 🎈 | 앞으로 똑바로 던짐, 맞으면 돎. 벽에 튕김 | 앞~중간 |
| 6 | 따라가는 물풍선 | 🎯 | 바로 앞 순위 카트를 따라가 맞힘 | 중간~뒤 |
| 7 | 자석 | 🧲 | 3초 동안 바로 앞 카트 쪽으로 끌려가며 가속 | 뒤 |

- 공부와 연결: 💡 힌트 전구. 그리고 정답 콤보 3회 이상이면 다음 아이템 상자에서 좋은 아이템 확률이 오른다.
- 한 번에 아이템 1개만 들고 있음 (기존과 같음). 부스터 3개만 남은 횟수 표시.
- 맞았을 때 효과는 기존 바나나 스핀을 재사용하고, 방패가 있으면 막고 방패가 사라짐.
- 아이템마다 3D 모양(models.js)과 효과음(WebAudio 합성) 추가. 아이템 칸에 남은 효과 시간 표시.

## 4. 컴퓨터 상대
- 4명 → 7명 (총 8대). 출발 격자 2줄 × 4.
- 동물 3종 추가: 여우, 판다, 오리. 기존 동물과 같은 카툰 방식으로 새로 만듦. 메뉴 캐릭터 선택도 8종.
- 성격 3가지: 공격형(아이템을 앞 카트에 바로 씀, 안쪽 길), 안정형(정답률 높음, 방패 아낌), 장난꾸러기(바나나·꿀을 자주 깔음). 난이도 3단계는 그대로 속도·정답률에 곱해짐.
- 컴퓨터끼리도 부딪힘 (지금은 플레이어와만). 성능을 위해 가까운 카트끼리만 검사.
- 순위표·결과 화면·미니맵은 8대에 맞게 늘림.

## 5. 지형 개선
- 커브 기울기: 반경이 작은 커브일수록 도로 바깥쪽을 높임(최대 약 8도). 차와 카메라도 그만큼 기울어짐.
- 노면 종류: 트랙 정의에 구간별로 `surface: [[u0, u1, 'ice'|'sand'|'mud']]`. 얼음은 미끄러움(옆 미끄러짐 줄어드는 속도 느림), 모래·진흙은 느려짐 + 흙먼지. 컴퓨터도 같은 감속.
- 지름길: 트랙마다 1곳. 본 도로에서 갈라졌다 다시 합쳐지는 좁은 길(폭 약 14), 노면이 거칠어 느리지만 거리가 짧음. 부스터를 쓰면 이득. 컴퓨터는 성격에 따라 가끔 씀.
  - 구현: 지름길은 별도 중심선을 가진 두 번째 도로. 진행도(바퀴 계산)는 본 도로 기준으로 투영. 역주행·자동 구조·문제 문 위치는 본 도로에만 둠(지름길 안에는 문 없음).
- 지형 높이맵을 트랙 바깥으로 더 자연스럽게 이음 (도로 옆 급경사 줄이기).

## 6. 새 트랙 2개
기존 방식(직선·원호 조각, 높이 함수, 볼거리 위치) 그대로 데이터로 정의.
- **눈 산길**: 눈 덮인 침엽수, 얼음 호수 구간(노면 얼음), 구불구불한 오르막·내리막, 눈 터널, 굴러오는 눈덩이, 지름길(얼음 호수 가로지르기).
- **해안 도로**: 바다와 모래사장, 등대, 야자수, 물웅덩이(물보라·감속), 해안 절벽 위 다리, 갈매기, 지름길(모래사장, 노면 모래).
- 음악: 트랙마다 곡 1개씩 추가 (기존 시퀀서 방식).
- 확인: 도로끼리 겹침 0곳, 문·점프대·부스터 발판은 직선 위, 길이는 기존과 비슷(2,400~2,700).

## 만드는 사람이 정할 것

- 새 동물·아이템·배경 모델의 세부 모양.
- 지름길 위치와 모양.
- 파일 분리 단위의 세부.

### 설계와 달라진 점
- 파일 공유 방식: 공용 namespace `window.EK` 대신 일반 script 의 최상위 선언 공유 (기존 코드를 거의 고치지 않고 분리, 이름 겹침은 테스트로 검사).
- 테마별 지형·장식은 `js/themes.js` 로 분리 (world.js 가 너무 커지지 않게).
- 지름길: 본 도로 가장자리에서 나란히 갈라지고 양 끝이 깔때기처럼 넓음. 갈림점에서 바로 급하게 꺾이면 카트가 들어갈 수 없었음. 초원 지름길은 입구가 급해서 감속·드리프트가 필요함(반경 45 이상인 자리가 없었음).
- 초원 서킷 문 0.29 → 0.36: 지름길 출구 바로 뒤라 문제를 읽을 시간이 없었음.
- 무지개 별·자석의 가속은 기존 부스터 상태를 재사용(×1.4).
- 컴퓨터가 아이템과 별개로 바나나를 흘리는 것은 장난꾸러기만: 8대가 모두 흘리면 플레이어가 한 경주에 6~14번 미끄러져서 순위가 운으로 갈렸음(실패 기준). 바나나 수명 45초 → 25초.
- 출발 격자와 "트랙 바깥 지형 잇기"는 검토 후 설계대로 보완함: 2줄 × 4 격자, 높은 길 옆 땅을 1:4 비탈로 이음(사막 메사는 절벽이 특징이라 제외).
- 검토 후 고친 것: 점프대 바로 뒤 문 배치, 컴퓨터의 지름길 순간이동, 소리를 끄면 듣기 문제를 내지 않음, 지름길 위 아이템, 방패·별과 움직이는 장애물, 단어 읽기 끊김, 좁은 화면 글자 넘침, 메뉴에 남는 비눗방울.
- 성능 기준 "소프트웨어 렌더링 16fps": 이 환경(headless SwiftShader)에서는 확장 전 코드도 13fps 라 같은 기준으로 비교(확장 후 13~15fps, '빠르게'에서 컴퓨터 카트 외곽선 숨김).
